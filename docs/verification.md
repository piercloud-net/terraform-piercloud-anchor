# Verification — CI gates, review, live proof

This is the verification checklist `/impl` looks for: what CI proves on every PR, how independent review works in this repo, and what must be proven live (with which authoritative signal) before a change counts as done.

Read it together with [conventions.md](conventions.md) (review + public-safety rules) and [invariants.md](invariants.md) (S1 / C-A review blockers). The device-flow approval mechanics live in [tools/verification-browser/README.md](../tools/verification-browser/README.md).

## 1. How to use this file

1. Identify your change type in §4 and note its live-proof checklist.
2. Run the CI gates (§2): `gh pr checks <pr>` must be green (pass, or a legitimate path-gated skip) on the exact PR head SHA.
3. Get an independent review (§3): security first, verdict recorded on that SHA.
4. Prove live (§4) against a real anchor on the reviewed SHA; record the run URL and the observed signals in the PR.
5. Close out (§6): merge, PR note, vault note, kanban.

If a needed signal is missing from this file, that is a docs gap — add it in the same PR that needed it.

**Rule — no hand-rolled parsers in verification artifacts.** If a check needs to understand a structured format (YAML, JSON, shell/bash, HCL, …), parse it with a real parser — `yaml.v3`/PyYAML/Psych for YAML, `unbash` + `unbash-walker` for shell — or pin exact bytes; never tokenize in awk/grep/sed. A hand-written parser diverges from the real grammar one construct at a time, and every review round becomes another evasion class instead of the check converging (worked example: the b3b `flow_end` tokenizer took ~36 lens rounds and the harness's own LF/BOM shell scan accumulated four more evasion classes in r36 — glob-disable spellings, pre-`readonly` emptying shapes, a cwd swap, a decoy heredoc — all while its pins stayed green; both were migrated to real parsers in #195 — PyYAML `compose` for the spans and a Python byte predicate for the LF/BOM set). "Dependency-free/offline" is not a reason: a parser dependency is cheaper than the arms race — and the parser invocation must run **isolated** (`python3 -I`): with a plain `python3 - -B` the harness's cwd lands on `sys.path`, an in-tree `yaml.py` shadows the installed package, and the shadow owns the composed tree and the marks it reports, so every span pin describes the attacker's tree instead of the file's real bytes (#195 r37 HIGH).

## 2. CI gates

Twelve checks run per PR: ten in [`ci.yml`](../.github/workflows/ci.yml) plus `validate-package-version` and `validate-release-pr` in their own workflows. Most run on every PR; two are path-gated — when their trigger paths are untouched they still report `pass`, with the payload steps skipped.

| Check (job name) | Trigger | What it proves |
|---|---|---|
| `tofu fmt` | always | HCL is canonically formatted (`tofu fmt -check -recursive`). |
| `tofu validate (cred-free)` | always | `tofu init -backend=false` + `validate` pass for the root module AND `examples/quickstart`, with no provider credentials. |
| `key-material grep (from main)` | always | No JWK private `d` scalar and no PEM private-key block in tracked code; the patterns are enforced from `main`, so a PR cannot weaken its own check. |
| `SCP endpoint allowlist grep (from main)` | always | No forbidden provisioning-adjacent surfaces (the `rescue`/… stem list) in tracked `.tf`/`.sh`/`.yml`, and no netcup/API endpoint outside the allowlist (the list also carries the pc-control broker report endpoint `broker.piercloud.net` — the managed-run anchor-IPv4 push, authenticated by a per-run GitHub OIDC token, never a standing credential); also enforced from `main`. |
| `secret-print grep (C-A, from main)` | always | No bounded acronym-print, personal-token phrase, CLI auth-subcommand, or bearer-print shapes in `.yml`/`.sh`; from `main`. |
| `shared-origin grep (from main)` | always | No tracked `.tf`/`.sh`/`.yml` references the retired shared wildcard origin-pair secret prefix (issue #123); the pattern is enforced from `main`, so a PR cannot weaken its own check. |
| `unit-tests (scripts)` | path-gated | The committed script harnesses (banner workflow diff, token refresh, anchor IP selection, managed-input preflight/binding, sweep pre/post, naming scheme, hand-run NTFY_TOKEN guard, retention cap, policy naming, provider stopgap, public-log safety, edge origin-auth, config file mounts, per-anchor origin-ca, Gatus render, dynamic status-page puller, external watch, recording-witness, broker report, broker DNS, b3b broker-provision-DNS job shape, managed operator-plane pin) pass, and `bash -n` + `shellcheck -S warning` pass over `.github/scripts/**`. |
| `bind-proof e2e (Caddy fronting mock tang)` | path-gated | A real `clevis luks bind` + unlock runs through the repo's rendered Caddyfile against a mock tang — the Caddy-in-front path stays bind-proven. |
| `jq boolean-read guard (false != empty)` | always | No boolean field is read with jq's `// empty` (jq treats `false` as empty; live-found 2026-09-10). |
| `scrub-canary (redactor proof)` | always | The poll-failure redactor still strips passwords, JWK `d`, and PEM bodies from log dumps and respects its byte bound. |
| `validate-package-version` | always (PRs to `main`) | `package.json` version discipline holds (release pipeline `cad0p/semver-calver-release`). |
| `validate-release-pr` | always (PRs to `main`) | Release-PR rules hold (e.g. `CHANGELOG.md` edits only on release branches). |

Path-gated triggers (from the gates in `ci.yml`):

- `unit-tests (scripts)` runs when a changed path matches `^(\.github/scripts/|\.github/workflows/|scripts/(lib/|010-provision\.sh)|tests/(banner-workflow-diff|anchor-ip-selection|scp-token-refresh|config-file-mounts|sweep-pre-classify|sweep-post-shapes|naming-scheme|ntfy-token-handrun|retention-cap|policy-naming|provider-stopgap|public-log-safety|gatus-render|gatus-pull|external-watch|managed-inputs|managed-operator-plane|broker-dns|broker-provision-dns|edge-origin-auth|origin-ca|recording-witness|broker-report)/|.*\.tf$)`.
- `bind-proof e2e` runs when a changed path matches `^(scripts/|\.github/workflows/|tests/bind-e2e/)|\.tf$`.

On push to `main` both path-gated jobs run unconditionally. If the changed-file list cannot be determined, both run (fail-open to extra proof).

How to read checks:

```bash
gh pr checks <pr>            # one line per check: pass / fail / pending / skipping
gh pr checks <pr> --watch    # wait until all checks settle
gh run view <run-id> --log   # full log when something is red
```

A path-gated job that reports `pass` with its payload steps skipped is green for merge purposes: it means the changed paths cannot affect what that job proves. Anything else red is a blocker — fix on the branch and re-verify, because a verdict applies to the commit it reviewed (§3).

## 3. Independent review + verify

Condensed from [conventions.md](conventions.md#review-protocol-independent-review-security-first):

- An independent reviewer is a separate instance (human or agent) that did not author the change and reviews the artifact, not the author's account of it.
- Security is the first lens: S1 / C-A credential custody, exposure windows, injection into shell / HCL / `$GITHUB_ENV` / `$GITHUB_OUTPUT`, and fail-open behaviour.
- Findings must be reproduced before reporting: a failing command, a payload, or a reverted-fix test.
- The verdict is recorded in the PR and names the exact commit SHA it reviewed.
- Any commit pushed after a verdict needs a verify pass by a reviewer seeded with the finding (a fresh instance for agent reviewers); a verdict applies only to the commit it reviewed.

## 4. Live proof per change type

Live proof means running the real flow against a real anchor and capturing the authoritative signal — not re-reading a green CI check. Record the run URL, the commit SHA, and the observed values in the PR.

Every `mode=apply` in this file (§4 and §5) is a managed dispatch (`tenant` + `anchor_ref` inputs): a tenant-less or ref-less apply is refused in the banner job before any gate or device card (b3b, #189).

### Provisioning run (`scripts/`, `.tf`, workflows)

- [ ] Dispatch `provision.yml` `mode=apply` from the reviewed branch as a managed dispatch (`tenant` + `anchor_ref`; a ref-less apply is refused) and approve the device flow (§5).
- [ ] Anchor target is API-derived: the A-record value and the A1 SSH target equal the `GET /servers/{id}` address (resolve log) — no pasted-IP override exists.
- [ ] Fail-closed proof: a temporarily set non-matching `ANCHOR_IPV4` fails the run closed at the resolve step (no SSH/DNS action; the secret is removed afterwards). The log names the candidate count, never the address values.
- [ ] Run log assertions all pass: firewall policy created/attached; A1 window opened then closed (swept pre + post); tang thumbprint printed; Caddy + Gatus deployed; DNS upsert + verify-after-write; device-grant teardown revoked; the long-lived A1 SSH carries keepalives (`ServerAliveInterval=30`/`ServerAliveCountMax=6`) so a silent witness acceptance cannot drop the session (issue #162).
- [ ] `dig +short anchor-01-<tenant>.piercloud.net` returns the anchor IPv4 (DNS-only record — clevis must reach tang directly, no edge in front).
- [ ] `curl -s -o /dev/null -w '%{http_code}' http://anchor-01-<tenant>.piercloud.net/adv` prints `200` from the main box, and times out from an unlisted address (the firewall actually gates tang).
- [ ] `curl -s -o /dev/null -w '%{http_code}' https://<tenant>.status.piercloud.net/` prints `200`, and the statuses API returns data (through the platform status edge).
- [ ] Per-anchor cert, operator runs (issue #123; managed runs read `ORIGIN_CA_CERT_PEM` from their environment only (#204), see `usage.md` §2; A2: a public single-SAN cert for the nested status host — interim: operator-obtained and pasted into the `ORIGIN_CA_CERT_PEM` variable as a leaf-first chain; the platform-broker ACME DNS-01 path is the M1 follow-up — Cloudflare Origin CA is dead for the CloudFront leg): the run log shows the on-box key + CSR present-or-generated (never any key material), the `origin-ca-csr-<tenant>` artifact is uploaded (also on a failed run — the CSR is captured before the original status is returned), the cert-only `ORIGIN_CA_CERT_PEM` variable (when set) validates fail-closed and installs (A2: the leaf-first chain is enforced — a leaf-only value or a chain whose blocks are not each exactly one X.509 cert (no trailing DER) with a CA:TRUE, non-duplicate issuer per hop is refused before install; under the interim AOP path a single Origin CA cert is accepted by design); no retired shared-pair secret prefix appears in the run env or logs; the CSR artifact carries no netcup account identifiers.
- [ ] No key material in state/plan (CI key-material grep + the provisioning script's own assertion); the thumbprint is saved in the password manager.
- [ ] Firewall shape: main box + the platform edge only, `:80` tang + ACME (main box + Cloudflare edge ranges), `:443` the CloudFront origin-facing prefixes + main-box `/32` (A2; no main-box IPv6 rule — the Caddy bypass is v4-only), egress ACCEPT-all, no SSH left open.

### Concurrency lane / tenant environment (`provision.yml`)

- [ ] **Managed lane**: dispatch with `tenant=<env>` **and** `anchor_ref=<ref>`; the run serializes in the `anchor-<ref>` lane, the ungated-banner preflight passes, the tenant-environment binding check passes (the environment carries `MANAGED_TENANT=<env>`), and the device-flow / `anchor-dns` jobs deploy under `<env>` (the environment's deployment activity names the run).
- [ ] **Lane separation**: with one run in flight (`anchor_ref=A`), a second dispatch with `anchor_ref=B` reaches `in_progress` (not queued); a third dispatch with `anchor_ref=A` stays non-running (`pending`/queued) while the first runs. Cancel the proof runs before any approval — no access token is minted without the tap.
- [ ] **Fail-closed (shape)**: a dispatch with `tenant=<env>` and an empty `anchor_ref` stops at the preflight step in the **ungated banner job** — before the environment protection gate on `device-flow` (so an opted-in reviewer is never paused for a run that cannot proceed) and before the device card. A ref-less or tenant-less `mode=apply` also stops there (b3b, #189: the anchor DNS stage needs the broker's managed binding + same-run report — the template/static apply lane is retired) and is refused **before any provisioning**; a **tenant-less**, ref-less `update-ip`/`destroy` (neither touches anchor DNS) warns loudly instead (the disclosed residual; a tenant-set dispatch without a ref fails closed in every mode).
- [ ] **Fail-closed (binding)**: a `tenant=<env>` dispatch whose environment does not carry `MANAGED_TENANT=<env>` (auto-created or partial env) stops at the device-flow binding check before any netcup use.
- [ ] **Operator-plane isolation (#198, #204)**: a `tenant=<env>` dispatch reads its operator-plane values from `<env>` only. With any of the repo-scope names defined at repository or organization level, the ungated banner job's `Repo-scope check` step refuses the managed dispatch before any gate or device card and names the names (never the values); with none, it logs `Repo-scope check ok (<N> names, …)`. An operator run (empty `tenant`) skips the check. `TENANT_USER` and `CUSTOMER_NUMBER` stay operator-only (gated): the banner job's summary names `<env>` (not the operator alias), the artifact is `head-sha-<env>`, and without the environment's `TENANT_CUSTOMER_NUMBER` the binding check stops the run before the device card. `tests/managed-operator-plane` pins every `secrets`/`vars` reference outside the named operator-only workflows (`ci.yml`, `external-watch.yml`) to a gated literal, a named shared/tenant-only literal, a bare read inside a job whose `environment:` is the tenant expression, or a presence probe inside the repo-scope step (the probe set must equal the declared environment-scoped name set — the pin's declared direct names plus its environment-only names `MANAGED_TENANT`/`TENANT_CUSTOMER_NUMBER`, not the observed bare reads); every job-level `environment:` is a per-file exact allowlist (the tenant expression in `provision.yml`, `inputs.environment` in the broker selftest, nothing anywhere else — a static `environment: anchor` on `anchor-dns` or on a new job is refused in-repo, on top of the broker's registry refusal) — and the `environment:`/`permissions:`/`if:` locators match their KEY case-insensitively, so a `Environment:`/`Permissions:`/`If:` spelling is judged instead of skipped (GitHub's schema is case-sensitive, so such a key cannot execute: this is consistency with the file's case-insensitive assumption, never an allowance — the tenant-environment read allowance stays exact, so a case-variant environment job still reds on its bare reads); `device-flow`'s gate order is pinned whole (`needs:` exactly `visibility-banner`, and no `if:` at all) and no job or workflow may grant the `actions` scope (the refusal only sees a DECLARED `permissions:` block, so every workflow file must declare exactly one workflow-level mapping: a file with none would inherit the repository/org default token scopes unscanned — all seven declare one, so a new file reds the pin instead of escaping it); a workflow file must compose to exactly one YAML document (a second one is reported by name, never scanned silently); and the `secrets`/`vars` scan is expression-scoped — only text inside a `${{ ... }}` expression is judged, so a `run:` line, a shell variable named `vars`, an unquoted date and `secrets.GITHUB_TOKEN` are not false reds, while an unterminated `${{` opener fails closed — and the slice follows the runner's own lexer: a single-quoted literal may contain `}}` (`''` is an escaped quote in-string, `'` toggles), so `${{ '}}' == 'x' && 1 || secrets.X }}` is judged whole, and a divergence from GitHub's parser (no `}}` outside a string, a string left open, a nested `${{`) fails closed; the step and the banner job carry no `if:`/`continue-on-error`; workflow, banner-job and banner-step keys are allowlisted (no `defaults:`, `shell:` or extra step keys); the preflight and repo-scope steps are banner steps 1–2, each pinned by a digest over its name, env and run text; `vars.MANAGED_TENANT` and the tenant customer-number form are read only inside tenant-environment jobs (a job outside the banner closure can use only the global gated/shared forms); every tenant-environment job reaches `visibility-banner` through its `needs:` closure with no status function (`always()`, `failure()`, `cancelled()`, `success()`) in an `if:`, and YAML anchors/aliases are refused (PyYAML node walk, default deny). Every `uses:` must be one of the exact allowlisted values (composite actions read the calling job's `vars` and are not scanned), and local `uses: ./`, `workflow_call`/`workflow_run`/`repository_dispatch` triggers and non-core YAML tags fail closed. The pin is a drift guard over the committed workflow text, not a boundary: the separation itself is GitHub's environment/secret scoping plus the workflow text on the executed ref. A change that edits both the workflow and the pin passes it, and so does one that removes the `ci.yml` run step and updates the broker-provision-dns blob-hash pins in the same PR (a review control). PyYAML (YAML 1.1) is not GitHub's parser; a parse difference that splits an expression leaves the context word in place and fails closed. A malformed tenant name (`pier-2`, `my_tenant`, 16+ characters, a reserved prefix) stops at the preflight, before any gate — and the canonical validator (`scripts/lib/naming.sh`, re-run by the binding step and by the operator resolve path) carries that same dispatcher grammar `^[a-z0-9]{3,15}$` plus the reserved prefix/name rules, so a console hand-run path refuses what the dispatcher refuses.
- [ ] **Environment selection is real**: a `tenant=<env>` dispatch from a ref the environment's deployment branch policy excludes is refused *because the environment was selected* (an empty-`tenant` run would have started) — record the refusal message.

### Broker report / anchor IPv4 (`broker-report.sh`, `provision.yml`)

- [ ] CI green; `tests/broker-report/run-test.sh` exercises the real lib against a stubbed curl (audience-tagged OIDC request, the broker POST, token-never-in-argv, input validation, every refusal path) and pins the workflow wiring.

- [ ] **Fail-closed**: a report against an unknown/ambiguous anchor_ref, a non-registry environment, or a foreign repository answers non-200 and the run fails at the report step (before the A1 window) — reproduce one locally with the selftest workflow or a bad ref.
- [ ] **Selftest canary**: dispatch `broker-report-selftest.yml` with the proof environment + a seeded anchor ref (the broker allowlists the selftest workflow only during the proof window) and record the run URL + registry read-back.
- [ ] **Unmanaged runs unaffected**: a manual/template run (empty `tenant`) skips the step (no report, no OIDC token request).

## 5. Device-flow approval (CfT PierCloud)

Every netcup use is human-approved per run (S1) through Keycloak's device grant. Approval happens in the branded **CfT PierCloud** browser — a Chrome for Testing instance with its own keychain item, cryptographically separate from personal Chrome — never in the personal browser (wrong profile = wrong session) and never in CI (a stored session would be a standing credential).

**Setup when absent (macOS):** `tools/verification-browser/build-app.sh` (fetch CfT, brand, ad-hoc sign) → `launch.sh` (idempotent, CDP `:$CDP_PORT`) → sign in to netcup SCP **in that window** (one-time `Chromium Safe Storage` keychain prompt → Always Allow). Mechanics and env knobs: [tools/verification-browser/README.md](../tools/verification-browser/README.md).

**Pre-flight:** `tools/verification-browser/approve-device.sh --preflight` (or open `https://www.servercontrolpanel.de/scp-ui/` in the automation profile). Authenticated shows the SCP UI; unauthenticated redirects to the Keycloak sign-in form. If the form appears, the session is gone — sign in inside the CfT window; a login in the personal browser does not help. This is the `NOT_CONFIRMED` failure mode.

**Approval sequence:**

1. Code lifetime ~10 min, poll window ~570 s.
2. Run `tools/verification-browser/approve-device.sh <run-id>`: it resolves the device URL from `--device-url` / `DEVICE_URL`, then ntfy (`--ntfy-topic` / `NTFY_TOPIC` with a required `--ntfy-token` / `NTFY_TOKEN` — an untokened topic is spoofable and refused; the token needs read access), then the live run-page log read through the verification browser itself (the CfT window is navigated to the device-flow job page; bounded), then the notice annotation (bounded; post-step only) — pre-flights the profile, navigates, confirms the Keycloak Grant Access page, clicks `#kc-login`, and polls for `/realms/scp/device/status` + `Device Login Successful` → prints `DEVICE_LOGIN_SUCCESSFUL`.
3. Manual fallback: open the live run page, read the device URL from the streaming `S1 device-flow` step log, navigate the CfT window there, click Grant Access, confirm the success page — or pass that URL to the script with `--device-url` (run id optional on that path).

**Redaction:** never print or paste the `user_code`; `approve-device.sh` redacts `user_code=…` in every URL it prints. The `device_code` is masked at birth inside the single-job flow and never crosses job boundaries; the `user_code` is public by design (it is the approval surface), lives ~600 s, and is useless without the profile's own session.

**Failure modes:**

- `NOT_CONFIRMED` — the profile lost its SCP session or the click did not land. Sign in inside the CfT window, re-run the approval script; if the run already failed its poll, re-dispatch.
- Fresh sign-in on the grant page — expected intermittently: the device-flow client runs its own SSO and does not inherit a warm `scp-ui` session; complete the sign-in in that window when asked.
- Device grant disabled — STOP + escalate; no fallback exists (C-A), see [dr.md](dr.md).
- Runner killed before teardown — the refresh token can stay live up to ~30 days; revoke the offline session in netcup's Keycloak, then re-dispatch (see [dr.md](dr.md)).
